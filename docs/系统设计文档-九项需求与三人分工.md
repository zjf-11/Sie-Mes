# IIDP 平台 MES 系统设计文档

**版本**：V1.0  
**范围**：需求 1–9（通用 MES 七项 + 保温杯生产管理 + 应用拆分）  
**平台**：IIDP 3.0（sie-snest-engine + sie-snest-sdk）  
**团队规模**：3 人

---

## 1 文档说明

### 1.1 目的

本文档描述基于 IIDP 低代码平台构建的 MES 系统的总体设计、数据设计、功能设计、接口设计与团队分工，作为开发、联调、验收和后续维护的依据。

### 1.2 读者

- 开发人员：了解模块边界、模型字段、服务契约与编码规范
- 项目负责人：了解排期、工作量与风险
- 验收人员：对照需求追踪矩阵与测试用例进行验收

### 1.3 术语

| 术语 | 说明 |
|---|---|
| APP | IIDP 平台的应用单元，一个 jar 包，含 model/views/app.json |
| 模型（Model） | 平台的元数据单位，对应一张业务表 + 一组标准服务 |
| 视图（View） | 平台页面描述文件，分 grid（列表）/form（表单）/search（查询）三类 |
| 服务（Service） | 模型上的方法，可通过 JSON-RPC 调用，分标准服务与自定义服务 |
| 台账 / 履历 | 主数据（产品、物料）与过程记录（工序履历、检测记录）的区分 |
| 锁定闭环 | 检测不合格 → 锁定批次 → 处置 → 复测放行 的完整链路 |

## 2 项目概述

### 2.1 背景

实训项目要求在 IIDP 平台上完成一套制造执行系统（MES）的核心功能，并在此基础上完成一个行业化的生产管理系统，且要求按业务模块拆分应用。

### 2.2 建设目标

1. 用平台能力（模型 + 视图 + 服务）完成产品、物料、BOM 的基础台账管理，不写前端页面代码。
2. 用平台模型实现可配置的编码规则，并提供通用编码生成服务，让业务数据的编码由规则驱动而非硬编码。
3. 面向保温杯制造场景，实现"批次追溯 + 质量检测 + 异常锁定"的闭环，体现业务规则而非单纯 CRUD。
4. 按业务域把行业系统拆成多个 APP，验证"分应用开发、统一入口使用"的工程组织方式。

### 2.3 范围边界

**范围内**：产品/物料/BOM 台账、编码规则与编码服务、保温杯 SKU/工单/批次/工序履历、真空焊参数、抽真空检测、温降测试、首件确认、异常处置、物料谱系。

**范围外**：ERP 财务与销售、单只杯唯一码（一物一码）、设备预测性维护、报表大屏、移动端。

## 3 需求分析

### 3.1 需求清单

| 编号 | 需求 | 类型 | 验收要点 |
|---|---|---|---|
| R1 | 产品管理页面（名称、规格等） | 功能 | 页面可增删改查，含规格字段 |
| R2 | 物料管理页面（名称、编码唯一） | 功能 | 编码重复被拒绝 |
| R3 | 产品 BOM 标签页，显示关联物料，带数量 | 功能 | 产品表单内可见 BOM 子表 |
| R4 | 产品 BOM 添加、删除 | 功能 | 标签页内可增删行 |
| R5 | 编码规则增删改查 | 功能 | 规则可维护，列表可查 |
| R6 | 编码规则含前缀、流水号位数、日期格式 | 功能 | 三项可配置且生效 |
| R7 | 提供按规则生成编码的服务，并用于业务模型 | 功能 | 新建产品/物料编码自动生成 |
| R8 | 保温杯生产管理系统 | 业务 | 批次全流程 + 质量锁定闭环 |
| R9 | 按模块拆分 APP | 架构 | 拆成多个可独立部署的 APP，菜单统一入口 |

### 3.2 关键用例

**UC-01 新建产品（自动编码）**：录入名称、规格 → 系统按 PRODUCT 规则生成 `P + yyyyMMdd + 5 位流水` → 保存 → 列表可见新编码。

**UC-02 维护产品 BOM**：打开产品表单 → 切到"产品 BOM"标签页 → 新增行（选物料、填数量）→ 保存；删除行同理。数量必须在 1–999999。

**UC-03 编码规则校验**：新增规则时规则编码重复 → 提示"规则编码已存在"；生成时规则不存在 → 提示"编码规则不存在，请先维护"。

**UC-04 抽真空检测不合格**：录入检测明细（真空度 60 Pa > 标准 40 Pa）→ 系统判定不合格 → 批次置锁定 → 生成异常处置单 → 该批次禁止新增工序履历。

**UC-05 异常处置放行**：在异常处置单填写处置方式与复测结果 → 确认 → 批次解除锁定 → 工序可继续流转。

### 3.3 非功能需求

| 项 | 要求 |
|---|---|
| 响应时间 | 列表查询 < 1s（千级数据） |
| 并发 | 编码生成必须避免重复（同期同规则的流水号唯一） |
| 可维护性 | 业务规则集中在服务层，视图不含逻辑 |
| 可扩展性 | 新增业务域以新增 APP 方式接入，不改动已有 APP |
| 数据完整性 | 编码唯一约束下沉到数据库；删除产品级联清理 BOM |

### 4.2 应用划分

| APP | 包名 | 职责 | 主要模型 | 依赖 |
|---|---|---|---|---|
| `mes` | com.sie.app.mes | 通用 MES 台账 | product、material、product_bom、code_rule | — |
| `cupbase` | com.sie.app.cupbase | 保温杯基础数据 | product_sku、equipment_mold、cup_sequence | — |

| `cuptrace` | com.sie.app.cuptrace | 异常与追溯 | exception_disposition、material_lot_genealogy | cupprod |

**拆分依据**：平台没有 APP 间运行时依赖机制（`app.json` 的 `dependencies` 不被引擎读取），因此：

- **编译期**：用 Maven 模块依赖解决跨 APP 的类引用（cupqc 需要 ProductionBatch 类型）
- **运行期**：引擎统一加载全部 jar，类加载器共享，跨 APP 的 `@ManyToOne` 按类名解析
- **打包**：repackage 插件配置 `classifier=exec`，主构件保持普通 jar 供下游编译，胖包以 `-exec.jar` 进 `apps/modules`

### 4.3 部署架构

| 组件 | 端口 | 说明 |
|---|---|---|
| nginx | 30666 | 静态资源 + /api 反向代理 |
| IIDP 引擎 | 8061 | 单实例，`engine.run.mode=single` |
| sie-grant | 8080 | 授权服务，引擎启动时注册 |
| MySQL | 3306 | 库 `iidp_demo_v3` |
| Redis | 6379 db5 | 元数据缓存，**必须 5.x**（3.2 会 Redisson 超时） |

### 4.4 关键设计决策

| 决策 | 方案 | 理由 |
|---|---|---|
| 编码规则存储 | 自建 `code_rule` 模型 | 平台内置 `encoder_rule` 模型不在本地 jar 中，无法使用 |
| 编码并发控制 | 服务方法 `synchronized` + 数据库唯一键兜底 | 单实例部署足够，唯一键防跨进程重复 |
| 日期段归零 | 记录 `seq_date`，日期段变化即流水归零 | 满足"按日/按月重新编号"的常见诉求 |
| 批次状态更新 | `DbUtils.updateByFilter` 增量更新 | `DbUtils.update(entity)` 会整行序列化回写，遇到关联预取结构报 `NotSerializableException` |
| 关联字段显示 | 目标模型编码字段标 `displayForModel=true` | 否则列表显示的是关联记录主键 id |
| 删除产品 | 服务内先删 BOM 再调 `callSuper` | 平台不自动级联；直接调 `rs.delete()` 会无限递归 |

## 6 功能设计

### 6.1 产品管理（R1）

**模型** `product`：name（名称）、code（编码，唯一）、spec（规格）、status（1 设计中 / 2 生产中 / 3 已完成）、productBomList（一对多）。

**服务**：标准 CRUD + 覆写 `create`（编码为空时按 PRODUCT 规则生成）、覆写 `delete`（级联删除 BOM）。

```java
public RecordSet create(RecordSet rs, List<Product> valuesList) {
    for (Product item : valuesList) {
        if (isBlank(item.getCode())) item.setCode(CodeRuleGenerator.nextCode("PRODUCT"));
        item.setCreate_user(rs.getMeta().getUserId());
    }
    return (RecordSet) rs.callSuper(Product.class, "create", valuesList);
}
```

**页面**：`product_grid`（名称/规格/编码/状态）、`product_form`（含 BOM 标签页）、`product_search`。

### 6.2 物料管理（R2）

**模型** `material`：name、code（唯一）、type（字典 material_type）、unit（字典 material_unit）、stock_quantity、price、supplier（多对一）、description。

**编码唯一性三重保障**：注解 `@Validate.Unique(properties={"code"})` → 服务内 `DbUtils.count` 显式校验 → 数据库唯一键。

### 6.3 产品 BOM（R3、R4）

**模型** `product_bom`：product、material、amount（1–999999）。

**页面**：产品表单 `tabs[0]` 指向集合属性 `productBomList`，`type=grid,form`，支持行内新增/删除（`createEr`/`deleteEr`）与编辑（`updateEr`）。

**删除策略**：删除 BOM 行使父产品的集合重新保存；删除产品时由 `Product.delete` 先删 BOM。

### 6.4 编码规则与编码服务（R5、R6、R7）

**模型** `code_rule`：name、code（规则编码，唯一）、prefix、seq_length（默认 5）、date_format（默认 yyyyMMdd）、current_seq、seq_date、remark。

**编码结构**：

```
code = prefix + format(dateFormat, now) + zeroPad(current_seq, seq_length)
例：P + 20261108 + 00002 → P2026110800002
```

**算法**：

```
nextCode(ruleCode):
  rule = select code_rule where code = ruleCode
  if rule == null:
      if ruleCode in (PRODUCT, MATERIAL): rule = 默认规则并落库
      else: throw ValidationException("编码规则不存在")
  datePart = rule.dateFormat 为空 ? "" : format(rule.dateFormat)
  if datePart != rule.seqDate: seq = 1
  else: seq = rule.currentSeq + 1
  if seq > 10^seqLength - 1: throw ValidationException("流水号已达上限")
  update rule(current_seq=seq, seq_date=datePart)
  return prefix + datePart + zeroPad(seq, seqLength)
```

**对外服务**：`code_rule.generateCode(ruleCode)`，`auth=read`。

**被业务模型使用**：`Product.create`、`Material.create` 在编码为空时调用；保温杯侧四类编码（SKU/工单/批次/炉次）由 `CupCode.nextCode` 复用同一套序列表 `cup_sequence`。

### 6.6 质量锁定闭环（R8 核心）

```
检测录入(vacuum_pump_run_batch)
   │  vacuum_reading > 40 Pa
   ▼
test_result = 2（不合格）  lock_flag = true
   │
   ▼
LockSupport.lockBatch(batchId)
   ├─ 批次 status = 3（锁定）、lock_flag = true
   └─ 生成 exception_disposition（异常类型、来源记录 id、待处置）
   │
   ▼
ProcessHistory.create 拦截
   └─ 批次已锁定 → 抛 ValidationException("批次已锁定，禁止流转到下一工序")
   │
   ▼
exception_disposition.dispose(处置方式, 复测结果)
   ├─ 处置记录更新（disposition、retest_result、unlock_flag）
   └─ 批次 status = 1（在制）、lock_flag = false
```

**设计要点**：

- 锁定与解锁都只改批次的两个字段，用 `updateByFilter` 增量更新，避免整行回写
- 异常单的来源记录类型区分检测明细（2）与温降（3），便于追溯
- 锁定状态下仅阻断"新增工序履历"，不阻断查询与处置，保证可修复

### 6.7 真空焊参数判定

| 参数 | 正常范围 | 越界处理 |
|---|---|---|
| 焊接电流 | 80–120 A | param_status = 2（异常） |
| 焊接时间 | 1.5–3.0 s | 同上 |
| 气体流量 | 8–15 L/min | 同上 |
| 任一参数为空 | — | 拒绝创建 |

### 6.8 温降测试

`result=2`（不合格）时复用 `LockSupport.lockBatch`，异常类型记为温降（来源类型 3）。`curve_data` 以 JSON 字符串保存整条温度曲线，供后续分析。

### 6.9 首件确认

按批次 + 工序 + 版本号记录首件照片 URL 与确认结果；换色换版场景要求先确认（当前版本以人工流程约束，未做强制拦截）。

## 7 接口设计

### 7.1 RPC 规范

- 地址：`POST /root/rpc/service/`
- 鉴权：`Authorization: Bearer <token>`（`POST /root/rpc/login` 获取）
- 报文：`{"id":"<guid>","jsonrpc":"2.0","params":{"context":{...},"app":"<app>","model":"<model>","service":"<svc>","args":{...}}}`

**参数按名字绑定**：服务方法形参名即 args 的键名。例如 `create(RecordSet rs, List<X> valuesList)` 必须传 `{"valuesList":[{...}]}`。

### 7.2 标准服务参数

| 服务 | args |
|---|---|
| search | `{"filter":"","properties":["*"],"limit":20,"offset":0,"order":""}` |
| read | `{"ids":["<id>"],"properties":["*"]}` |
| create | `{"valuesList":[{...}]}` |
| update | `{"ids":["<id>"],"values":{...}}` |
| delete | `{"ids":["<id>"]}` |
| count | `{}` 或带 filter |

## 8 三人分工

### 8.1 角色定义

| 角色 | 定位 | 能力要求 |

### 8.5 协作规范

**分支策略**：`main` 保护分支；每人 `feat/<模块>` 开发；每日合并前跑一次全量构建。

**接口先行**：W8/W11 开始前，先冻结"表结构 + 服务签名 + 视图命名"，三方按契约并行，不相互等待。

**代码评审**：跨模块改动必须由另一人评审（如 A 改 C 的 APP 需 C 复核）。

**命名规范**：
- 模型名小写下划线（`production_batch`），类名大驼峰
- 编码字段统一 `xx_code` / `xx_no`
- 服务名动词开头（`generateCode`、`dispose`、`lock`）
- 视图名 `<model>_grid|form|search`

**提交规范**：`<type>(<scope>): <subject>`，type ∈ feat/fix/docs/refactor/chore。

**环境约定**：开发共用一套 8061 单实例；改 jar 前必须停服（否则 `apps/modules` 文件被占用）；重启后如报"元模型不存在"，执行 `UPDATE meta_app SET md5='' WHERE loader_type='SDK'` 触发重建。

### 8.6 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台元数据缓存丢失（Redis 被清） | 后端启动失败 | 禁止 flush db5；用 md5 置空重建；重建后 `redis-cli save` |
| 打包插件替换主构件 | 跨模块编译失败 | `classifier=exec` 配置 |
| 整行回写序列化异常 | 锁定/解锁报错 | 统一用 `updateByFilter` 增量更新 |
| 关联字段显示 id | 页面可读性差 | 编码字段标 `displayForModel=true` |
| 字典数据不全（material_type） | 物料类型录入被拦 | 补齐字典或先用自由文本 |
| 工作量集中在中后期 | 尾期赶工 | 里程碑 M3/M4 提前冻结接口，C 的工作从 D3 起并行 |

|---|---|

### 10.2 构建

```bash
mvn -o -Daether.enhancedLocalRepository.trackingFilename=_remote.repositories.bak \
    -s offline/offline/maven/settings.xml \
    -Dmaven.repo.local=offline/offline/maven/repository \
    -f iidp-backend-demo/sie-iidp-demo-apps/pom.xml \
    -pl sie-snest-mes,sie-snest-cup-base,sie-snest-cup-prod,sie-snest-cup-qc,sie-snest-cup-trace \
    -am package -DskipTests
```

### 10.3 启动顺序

1. MySQL（3306）
2. Redis 5（6379，db5）
3. sie-grant（8080）
4. 引擎（8061，工作目录必须是 `iidp-backend-demo`，否则找不到 `apps` 目录）
5. nginx（30666）

### 10.4 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `元模型[...]在容器中不存在` | Redis 元数据缓存丢失 | `UPDATE meta_app SET md5='' WHERE loader_type='SDK'` 后重启 |
| 构建报 `另一个程序正在使用此文件` | jar 被运行中的 JVM 或 IDE 占用 | 停后端与 IDE 调试进程，重新打包 |
| `RedisConnectionException: TimeoutException` | Redis 3.2 版本过低 | 换 5.0 |
| RPC 报 `找不到服务` | 应用未注册或权限未授予 | 检查 apps.json、meta_app、rbac_role_auth |
| 关联列显示 id | 目标模型缺显示字段 | 编码字段加 `displayForModel=true` |

## 附录 B 平台踩坑记录

| 问题 | 结论 |
|---|---|
| 自定义 create 取不到参数 | RPC 按形参名绑定，第二个参数必须命名为 `valuesList` |
| `DbUtils.select(filter, "*", X.class)` 报错 | 第二个参数是模型名不是字段列表 |
| `DbUtils.update(entity)` 报 NotSerializable | 改用 `updateByFilter(map, filter, modelName)` |
| 跨模块编译找不到类 | repackage 加 `classifier=exec`，主构件保持普通 jar |
| 关联列显示主键 id | 目标模型编码字段加 `displayForModel=true` |
| `rs.delete()` 死循环 | 覆写 delete 必须调用 `rs.callSuper(...)` |
| 菜单/视图不落库 | 由 jar 内 views/*.json 运行期加载，改 jar 即改页面 |
| 清空 Redis db5 后启动失败 | 元数据缓存在 db5，只能靠 md5 置空重建 |
